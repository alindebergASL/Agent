# Retain a verified recovery method

This first recovery tool covers numeric import audits. To stage a reusable method, the model must cite reads from at least two distinct uploads, at least one calculator result, and a corrected artifact it has already staged. The runner checks that those receipts were in the model input for the staging request. The model judges whether they establish a recovery and describes the evidence. The two-upload and calculator requirements currently limit which recoveries it can save.

The app publishes the method with the corrected artifacts in the same SQLite transaction. Stop, correction, failure, and interruption discard the draft. The existing Saved methods page lets the user inspect the evidence and source assignment, edit the method, or remove it. A later run can retrieve the scope and procedure through `read_method`.

## Verification plan

Use the original supplier export and an attempted import generated by coercing its part identifiers to integers. The attempted import turns `000731` and `731` into duplicate `731` values. Upload both files, ask the agent to audit and correct the comparison for four units of each part across two shipments on one order, and ask it to retain the verified procedure. Keep source prices and other assignment details in the evidence or output files. The fixture defines both upload sets and the browser prompts. [Fixture](../tests/recovery_fixture.py)

## Verification notes

The controlled fixture changed only the identifier representation. Offline, all 34 Compose tests passed. The recovery tests checked source reads, corrected totals and citations, method retrieval in a new assignment, and disposal of staged methods and artifacts when Stop or correction preceded a delayed final response. [Recovery tests](../tests/test_recovery_methods.py)

In Codex Cloud, the live `gpt-6.2-sol` run read the original and lossy CSVs, identified the collision and recovered the two exact identifiers. The saved CSV and source rows agreed. Four units of `000731` at $41.50 plus two $8.40 charges cost $182.80. Four units of `731` at $57.25 plus one $11.30 charge cost $240.30. The staging receipt recorded both checked totals and the corrected CSV. The resulting method appeared in Saved methods with its procedure, evidence, and source assignment.

After container recreation with the same volume, the method and source assignment reopened. A fresh live request that omitted any mention of the method called `read_method` before writing its artifacts. The model returned both new identifiers as distinct text. Its scope and procedure contained no original supplier names, prices, identifiers, or task notes. The fresh CSV and Markdown cited the new source rows.

Each line total uses six units and the freight terms on that quote row. The combined comparison adds the two line totals for each supplier. The $13.60 advantage depends on that assumption.

The first live request explicitly asked the agent to save a method if it verified a repair. The fresh request asked only for a comparison. The demonstration established agent-authored saving and unprompted retrieval using the uploaded fixture files.
